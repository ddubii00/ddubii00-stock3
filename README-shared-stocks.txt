공유 종목 차트

헤더의 '종목' 목록(최대 20개)은 접속 암호를 통과한 모든 컴퓨터에서 공유합니다.
추가·삭제·순서 변경은 서버 저장 성공 후 표시하며, 다른 화면은 20초마다 동기화합니다.
같은 주소의 모든 이용자가 하나의 목록을 공유합니다. 개인별 목록은 아닙니다.
처음 한 번만 먼저 접속한 브라우저의 기존 목록을 가져옵니다. 이후 브라우저 저장값은
서버 목록을 덮어쓰지 않습니다. 빈 목록도 저장되며 서버 재시작 후 유지됩니다.

Oracle 서버
- 외국인 선물·프로그램 수급 표는 서버 환경변수의 기존 KIS 키를 우선 사용합니다.
  KIS_APP_KEY/KIS_APP_SECRET 및 기존 KIS_APPKEY/KIS_APPSECRET, KIS_KEY/KIS_SECRET,
  APP_KEY/APP_SECRET, APPKEY/APPSECRET 이름을 유지합니다. 다른 앱의 키 파일을 읽지 않습니다.
- KIS 키가 설정된 Oracle에서는 선물 행 전체를 계약 단위로 선택합니다. 수집 이력이 부족한
  3/5/10/20일 값은 '-'이며 현물 금액으로 채우지 않습니다. 직접 core 실행 시 선물은 최근값만 제공합니다.
- 프로그램은 KIS 일별(FHPPG04600001)과 시간별(FHPPG04600101)을 독립 조회합니다.
  일별 응답의 자기/위탁 대금 합계 및 차익 대금 필드 변형을 처리하고,
  장마감 후 15:30~17:00 동일 종가 응답도 반영합니다. 실패 코드는 화면 및 인증된
  /api/kis-flow-health의 programDiagnostics에서 확인합니다. 공개 대체 값으로 KIS 실패를 숨기지 않습니다.
- 실제 환경 점검: 코드 업데이트 후 기존 stock3 서비스를 재시작하고, 서비스와 같은 환경에서
  node scripts/check-kis-program.js 를 실행합니다. 휴장일/장 시작 전에는 최근 거래일을 지정할 수 있습니다.
  예: node scripts/check-kis-program.js 2026-10-20
  출력은 설정 여부·API별 상태·기준일·수급값만 포함하며 키/토큰/응답 원문은 출력하지 않습니다.
- 기본 저장 위치: 앱 디렉터리/.stock3-data/chart-stocks.json (Git 제외, HTTP 직접 접근 차단).
- 서비스 실행 계정에 해당 디렉터리 생성·쓰기 권한이 필요합니다.
- 선택 환경변수 STOCK3_STOCK_LIST_PATH로 앱 배포 경로 밖의 영구 경로를 지정할 수 있습니다.
  예: /var/lib/stock3/chart-stocks.json
- Docker라면 저장 디렉터리를 영구 볼륨에 연결하세요. 코드 갱신 때 저장 파일을 지우지 마세요.
- 파일 저장은 잠금과 원자적 교체를 사용합니다. 실패 시 경고와 API 오류를 반환하며 앱은 계속 실행됩니다.
- 기존 127.0.0.1 바인딩과 인증은 유지합니다.

Vercel 등 읽기 전용 환경
- 디스크/임시 파일 대신 공유 Redis REST 저장소를 사용합니다. 서버 환경변수에
  STOCK3_LIST_REST_URL, STOCK3_LIST_REST_TOKEN을 설정하세요.
  기존 KV_REST_API_URL, KV_REST_API_TOKEN도 지원합니다.
- Redis REST의 GET 및 EVAL 명령 권한이 필요합니다. 키는 stock3:chart-stocks:v1입니다.
  원자적 비교 후 저장으로 여러 인스턴스의 동시 변경을 보호합니다.
- Oracle와 Vercel에도 동일 목록이 필요하면 양쪽에 같은 Redis 저장소를 설정하세요.
- Vercel에서 공유 저장소가 미설정이면 오류를 표시하며 임시 저장 성공으로 처리하지 않습니다.
- URL/토큰은 서버 환경변수로만 제공하고 브라우저·저장소에 입력하지 마세요.

미국 종목
- 국내 이름/코드와 미국 회사명/티커(AAPL, NVDA, KO 등)를 같은 검색창에서 검색합니다.
- 애플·엔비디아·테슬라·마이크로소프트 등 주요 종목은 한국어 별칭도 지원합니다.
  그 외 회사는 영문명이나 티커로 검색하세요. NASDAQ/NYSE/AMEX의 주식·ETF를 지원합니다.
- 가격/시세: 기존 서버 KIS 환경변수로 해외주식 현재가를 우선 조회하고 Yahoo Finance로 보완합니다.
- 일·주·월봉 이력: Yahoo Finance, 실패 시 TradingView. 미국 종목을 KIS 지수 이력 API에 넣지 않습니다.
- 국면 계산은 뉴욕 정규장 종료 이후 확정 일봉을 사용합니다. 달러 가격은 소수 둘째 자리까지 표시합니다.
- 외부 원천의 지연/제공 범위/검색 제한은 서버에서 실제 확인해야 합니다.

상승추세 기준 고점
- 20일선 위 5거래일 연속 종가 마감 + 20일선 상승이 확인되면 이전 사이클의 기준 고점과
  분할 단계는 초기화합니다. 새 상승 확인 구간의 최고 종가부터 이후 최고 종가를 갱신합니다.
- 1~4일 반등이나 미확정 당일봉은 초기화하지 않습니다. 과거 단계 신호는 이력에 남습니다.
- 기존 120일선 위 10거래일 연속 + 60일선 10일 대비 상승도 새 사이클 확인 조건으로 유지합니다.

서버에서 확인할 항목
1. 두 컴퓨터에서 같은 서버 주소로 로그인하여 추가·삭제·순서 변경이 20초 이내에 동기화되는지.
2. 서버 재시작·배포 후 목록이 유지되는지, 서비스 계정의 저장 권한/볼륨이 맞는지.
3. Vercel 사용 시 Redis REST 설정과 GET/EVAL 권한, Oracle와 같은 목록이면 동일 저장소인지.
4. 미국 이름/티커 검색과 AAPL/NVDA/NYSE 종목의 KIS 권한·가격·거래소 코드·시세 지연 여부.
5. 미국 일·주·월·삼선 차트 이력과 휴장/미확정 당일봉 제외가 실제 원천에서 맞는지.
6. 이전 확인 요청 유지: data/vkospi.json spot/선물 연속물 구분, Daum perPage=130 및 원본 단위,
   Naver investorDealTrendDay sosok=03 생존 여부와 선물 계약 단위.

M2·수급·차트 표시 보완
- 한국 M2: RichCounter API 실패 시 KRED KRM2 공개 관측값으로 보완합니다. 원천 단위를
  확인해 조원으로 변환하며 제한된 관측 구간은 표시합니다. 미국은 FRED M2SL을 먼저 조회합니다.
- M2의 전년동월 자료가 없어도 수준 차트는 표시하며 YoY는 '-'로 둡니다.
- KIS 프로그램 일별 응답에서 전체 순매수 필드가 없으면 전체 매수-매도 또는 차익+비차익
  순매수 대금을 계산합니다. 한쪽 값이 없으면 결측으로 처리합니다. 단위는 기존 백만원→억원입니다.
- 현물 대체 이력과 별도로 KIS 선물 최근값(계약)을 표시하여 단위가 섞이지 않게 합니다.
- 등록 종목의 일·주·월봉에도 MACD 0선 배경색을 적용합니다(양수 빨강, 음수 파랑).
- 지수/종목 시세·차트는 20초 주기로 요청합니다. 브라우저가 숨겨졌거나 조회 중이면 중복 호출을
  막습니다. Yahoo 보완 시세는 정규장 regularMarketPrice를 쓰며 시간외 가격으로 덮지 않습니다.
- 서버 확인 추가: KIS 프로그램 일별 전체 매수/매도 필드와 백만원 단위, 최근 개장일의
  선물 계약값·프로그램 누적값, 한국 M2 대체 원천/단위/최신 발표월, 미국 M2 FRED 접속.
화면 선택 공유
- 헤더의 전체/일부/선택: 접속 기본값은 전체입니다.
- 선택에서 네 풀다운에 서로 다른 차트·대시보드를 지정하고 저장합니다. ×로 비운 칸도 저장됩니다.
- 일부는 저장된 네 칸을 2×2로 표시합니다. 큰 표는 각 칸 안에서 스크롤합니다.
- Oracle 기본 저장 파일은 .stock3-data/dashboard-selection.json입니다. STOCK3_STOCK_LIST_PATH를 쓰면 같은 폴더에 저장합니다.
- 별도 경로가 필요하면 STOCK3_DASHBOARD_SELECTION_PATH를 서비스 환경에 설정합니다. 환경 파일이나 키/토큰 파일을 만들거나 읽지 않습니다.
- Vercel에서는 기존 종목 공유용 Redis REST 환경변수를 함께 사용하며, 선택 목록은 별도 키로 보관합니다. 읽기 전용 파일시스템에는 저장을 시도하지 않습니다.
- 다른 기기는 접속하거나 20초 동기화 후 같은 선택을 읽습니다. 저장 실패 시 성공으로 표시하지 않습니다.
